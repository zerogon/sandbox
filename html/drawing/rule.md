# 휴양소 리조트 추첨 규칙

> 원본 분석 대상: `drawing.xlsx` (회사 구성원 리조트 신청 명단 기반 추첨 파일)
> 이 문서는 `html/index.html`의 "휴양지 랜덤 추첨" 기능을 자동화할 때의 사양서 역할을 한다.

## 1. 개요

- 구성원의 리조트 신청 명단을 받아 정해진 순서대로 리조트별 추첨을 진행한다.
- **추첨 순서:** 호반 → 롯데 → 대명 → 오크밸리 → 한화
- **핵심 규칙:** 앞 순서 리조트에서 당첨된 사람은 이후 리조트 추첨 대상에서 **제외**된다. (한 사람은 최대 1개 리조트에만 당첨)

## 2. 파일 구조 (9개 시트)

| 시트 | 역할 | 비고 |
|---|---|---|
| `휴양소 조회처리_0410` | 원본 신청 명단 | 266 신청건 |
| `호반` | 1순위 추첨 작업 시트 | 전체 266건 복사본 + 당첨/제외 표시 |
| `롯데` | 2순위 추첨 작업 시트 | 〃 |
| `대명` | 3순위 추첨 작업 시트 | 〃 |
| `오크밸리` | 4순위 추첨 작업 시트 | 〃 |
| `한화` | 5순위 추첨 작업 시트 | 〃 |
| `당첨` | 당첨된 **신청건** 모음 | 64건 |
| `낙첨` | 낙첨된 **신청건** 모음 | 202건 |
| `당첨자 목록` | 마스터 당첨자(사번) + 인원 단위 통보표(이메일) | 제외 판정의 기준 시트 |

- 5개 리조트 시트는 모두 원본 명단 266건을 **그대로 복사**한 사본이다(같은 행, 같은 순서). 각 시트에서 해당 리조트 신청자만 대상으로 추첨하고, 결과를 표시한다.

## 4. 추첨 규칙

### R1. 신청 단위이며 복수 신청이 가능하다
- 전체 **266 신청건**이지만 고유 인원은 **166명**.
- **50명**이 여러 리조트/룸타입에 중복 신청했다. (예: `이상대` 9건 = 호반5·롯데3·오크밸리1)
- 따라서 한 사람이 여러 곳에 당첨될 수 있고, 이를 막는 것이 R4다.

### R2. 추첨 순서 = 시트 순서
- 호반 → 롯데 → 대명 → 오크밸리 → 한화 순으로 진행한다.

### R3. 리조트 풀 내에서, (리조트 × 룸타입) 객실 정원만큼 추첨
- G열(리조트)로 묶인 신청자 중에서만 당첨자를 뽑는다.
- 당첨 인원은 룸타입(객실)별 가용 수량만큼 배분된다. (호반 예시: `S30 타워 클린` 61신청→6당첨, `G40 타워 클린` 11→2 …)

| 리조트 | 신청 인원 | 당첨 |
|---|---|---|
| 호반 | 135 | 19 |
| 롯데 | 67 | 17 |
| 대명 | 48 | 19 |
| 오크밸리 | 10 | 5 |
| 한화 | 6 | 4 |
| **합계** | **266 (신청건)** | **64** |

### R4. 중복 당첨 제외 (핵심 규칙)
- 앞 순서 리조트에서 당첨된 사번은 이후 추첨에서 제외된다.
- **구현 방식:** 각 리조트 시트의 `타객실 당첨`(Q열) 수식
  ```
  =IF(COUNTIF('당첨자 목록'!D:D, 사번) > 0, "당첨", "")
  ```
  마스터 `당첨자 목록`의 사번 열(D)에 해당 사번이 있으면 `"당첨"`으로 표시 → **추첨 제외 대상**.
- `당첨`(P열)에는 그 사람이 당첨된 **리조트명**을 기록하며, 시트가 뒤로 갈수록 누적된다. (한화 시트 P열에는 64명 전원이 호반/롯데/대명/오크밸리/한화로 라벨됨)
- `당첨자 목록` 시트의 D/E/F = 마스터 당첨자(사번/성명/리조트구분). F열은 각 리조트 당첨 블록의 시작점 라벨 역할.

### R5. 정원 내 선발은 완전 무작위
- 당첨 행이 시트 순서상 흩어져 있고(7·9·15·22…), 기사용일수(N열)로도 당락이 갈리지 않는다. (당첨자 N분포가 낙첨자와 비례적)
- → **신청 순서·이력과 무관하게 정원 내 랜덤 추첨**으로 선발한다.

### R6. 부가 컬럼
- O열 `신청일수`: 값은 전부 `신청` (사실상 신청 상태값).
- N열 `기사용일수`: `1(1)` / `1` 형식의 직전 사용 이력 표시이나 당락에는 반영되지 않는다.

### R7. 최종 산출물은 두 가지 단위
- **신청건 단위:** `당첨`(64건) / `낙첨`(202건) — 합 266 (전체 신청건).
- **인원 단위:** `당첨자 목록`의 I~L열(사번/성명/결과/이메일) = 최종 통보표.
  - 당첨 **63명** / 낙첨 **103명** = **166명** (고유 인원 전체). 이메일 발송용.

## 5. 추가 논의 필요 (Open Questions)

- **정원 산정 방식 (구현 전 필수 결정):** 리조트/객실별 당첨 정원이 입력 엑셀에 없다. 다음 중 결정 필요.
  - (a) 룸타입별 정원을 별도 표로 입력/업로드 (샘플 분포와 가장 일치)
  - (b) 리조트별 총원만 입력하고 룸타입 구분 없이 추첨
  - (c) 입력 엑셀에 정원 컬럼을 추가
- **신청건 64 vs 인원 63의 1건 차이:** 동일인 2건 당첨 추정 — 실제 데이터 확인 필요.
- **동일인·동일 리조트 다중 신청 행 처리:** 예) `부장원` 호반 7건 — 한 행만 당첨 처리하는지, 중복 행을 사전 정리하는지 규칙 명확화 필요.
