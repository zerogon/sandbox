# 개인 1·2지망 기반 추첨 전환 분석

작성일: 2026-07-27
대상: `drwing.html` (휴양소 추첨 도구) — 분석 시점 기준 최신 커밋 `3ca758e`
성격: 타당성 분석 문서 (코드 변경 없음)

---

## 1. 현재 방식 요약 — 우선순위의 주체는 "객실"이다

현재 추첨(`draw()`, `drwing.html` L707-828)의 우선순위는 전적으로 **리조트(객실) 기준**이다.

- 좌석을 `RESORT_ORDER`(L318: 호반 → 롯데 → 대명 → 오크밸리 → 한화) → `sortSlot`(L477: 지역 가나다순 → 입실일 → 타입) 순으로 펼치고(L743-750), Kuhn 최대 이분 매칭이 그 순서대로 배정한다(L752-768).
- Kuhn 알고리즘 특성상 먼저 처리된 좌석은 매칭을 절대 잃지 않으므로 **앞 리조트 = 절대 우선권**이며, 같은 리조트 안에서도 지역명 가나다순이 사실상 우선권이 된다.
- **개인 지망 데이터는 입력에도 자료구조에도 존재하지 않는다.** `target.xlsx`에 지망/순위 컬럼이 없고, 복수 신청은 "사번이 같은 행 N개"일 뿐 행 간 순위가 없다. 자료구조도 `객실그룹 → 신청자 집합`(역방향)만 있고 `사번 → 희망객실 순위 리스트`는 없다(`parseTarget` L488-532, `STATE` L380-387).
- 무작위성은 그룹별 후보 셔플(`secureShuffle`, L698-706)에서만 나온다.
- 부산물: 경쟁률 1:1 객실에 2건 이상 신청한 사람은 자동 배정하지 않고 "선택지메일" 대상으로 분리해(L794-823) 수동 배정한다 — **지망 정보가 없어서 생긴 수동 프로세스**다.

## 2. 결론: 개인 지망제 전환은 가능하다

변경 범위는 3곳으로 국한된다.

| # | 변경 지점 | 내용 |
|---|---|---|
| 1 | 입력 파싱 (`parseTarget` L500-501) | `target.xlsx`에 `지망` 컬럼 추가 후 1개 컬럼만 추가로 읽기 |
| 2 | 자료구조 | `STATE.apps` 원본 행에서 `사번 → [{객실그룹, 지망순위}]` 인덱스 재구성 |
| 3 | 매칭 알고리즘 (`draw()` L729-787) | 최대 이분 매칭 블록 교체. 출력 형태(`won/winners/slotResults`)를 유지하면 STEP5 렌더·엑셀 다운로드는 무수정 |

단, **신청 프로세스(엑셀 양식) 변경이 선행 필수**다. 기존 `번호` 컬럼(신청 순서)을 지망으로 간주하는 편법도 가능하지만, 신청자가 순서에 의미가 있는 줄 몰랐던 데이터라 공정성 시비 소지가 있다.

## 3. 알고리즘 대안 3종 비교

| 방식 | 동작 | 총 당첨 인원 | 구현 난이도 | 전략 조작 |
|---|---|---|---|---|
| A. 지망 티어드 Kuhn (보스턴 방식) | 전원의 1지망만으로 최대 매칭 → 남은 좌석에 2지망 매칭 | **감소 가능** (현재 66 미만) | 낮음 | 취약 — 인기 객실을 1지망에 쓰면 손해, 눈치작전 유발 |
| B. 최소비용 최대유량 (MCMF) — **권장** | 총 당첨 인원 최대(66 유지)를 제약으로, 지망 순위 비용 합을 최소화 | **유지** | 중간 (~100줄 추가) | 중간 |
| C. 무작위 순차 독재 (RSD) | 신청자를 셔플 → 순서대로 각자 남은 객실 중 최상위 지망 배정 | 감소 가능 | 매우 낮음 | **없음** (정직 신고가 항상 최적) |

B안을 권장하는 이유: 현재 알고리즘이 "실행마다 총 당첨 인원이 62~66으로 흔들리는 문제"를 잡으려고 최대 매칭으로 교체된 것(커밋 `15124c1`, `추첨_결과_분석.md` 참조)이라, 총원을 희생하는 A안은 퇴행이기 때문이다.

## 4. B안 단계별 동작

핵심 아이디어: **"사람을 한 명씩 배정하되, 자리가 막혀 있으면 이미 배정된 사람을 다른 지망으로 옮겨서라도 자리를 만들고, 옮기는 방법이 여러 가지면 지망 순위가 덜 밀리는 쪽을 고른다."**

1. **지망 표 만들기** — 신청 엑셀에서 사람별 지망 리스트 구성 (사번 → 1지망 객실, 2지망 객실).
2. **연결망(그래프) 구성** — 왼쪽 사람(1인 1객실), 오른쪽 객실(정원만큼 수용). 사람 → 신청 객실 간선에 비용 부여: 1지망 = 1, 2지망 = 2.
3. **가장 싼 길로 한 명씩 배정** — 무작위로 섞은 순서대로 처리. 1지망에 빈자리가 있으면 그냥 배정. 꽉 찼으면 "본인 2지망에 넣기" vs "기존 배정자를 그의 다른 지망으로 옮기고 1지망에 넣기" 중 비용이 싼 쪽을 자동 선택.
4. **재배치 예시** — 호반 A 정원 1. 철수(1지망 호반A, 2지망 대명B)가 먼저 호반A에 배정된 뒤, 영희(1지망 호반A뿐)가 오면: 그리디라면 영희 낙첨이지만, B안은 "철수를 대명B로 옮기면 영희가 들어간다"를 자동 발견 → **둘 다 당첨**. 이 재배치(증대 경로) 덕분에 총 당첨 인원이 항상 최대로 고정된다.
5. **종료** — 더 넣을 방법이 없으면 끝. 결과는 ① 총 당첨 인원 최대(현재와 동일) ② 그중 지망 비용 합 최소(1지망 당첨자 최대)가 수학적으로 보장된다.
6. **무작위성** — 비용이 같은 길이 여럿일 때만 셔플 순서로 결정(`secureShuffle` 재사용).

## 5. 두 기준 병행 — 하이브리드 구성

리조트 순서와 개인 지망은 충돌할 수 있어 둘 다 "1순위"일 수는 없다.

**충돌 사례**: 민수가 1지망 한화C, 2지망 호반A를 낸 경우 — 리조트 순서 기준이면 호반이 먼저 뽑으므로 민수는 호반A(2지망)에 배정될 수 있고(한화C에 빈자리가 있어도), 개인 지망 기준이면 한화C(1지망)에 가야 한다.

| | 리조트 순서 | 개인 지망 | 코드 변경량 | 규칙 문서 |
|---|---|---|---|---|
| 현재 | 1순위 | 없음 | — | — |
| 하이브리드 1 | **1순위 유지** | 객실 내 경쟁에서만 작동 | 몇 줄 (`cand[gk]` 후보 정렬만 변경) | 개정 불필요 |
| 하이브리드 2 | 타이브레이커로 강등 | **1순위** | 중간 (MCMF 도입) | 개정 필요 |
| 순수 B안 | 삭제 | 1순위 | 중간 | 개정 필요 |

- **하이브리드 1**: 객실을 지금처럼 리조트 순서대로 채우되, 한 객실 안에서 경쟁자를 고를 때 그 객실을 1지망으로 쓴 사람 → 2지망 → 동순위 무작위 순으로 뽑는다. 변경 최소·규칙 개정 불필요이지만, 위 민수 사례처럼 1지망에 자리가 있어도 앞 리조트(2지망)에 끌려갈 수 있어 지망제 취지가 절반만 산다.
- **하이브리드 2**: 지망이 항상 우선, 리조트 순서는 지망 만족도가 완전히 동률일 때만 개입. 상세는 6절.

판단 기준은 **리조트 순서가 왜 존재하는가**다. 회사 정책상 의미 있는 순서라면 하이브리드 1이 안전하고, 단지 처리 순서를 정하기 위한 임의의 순서였다면 하이브리드 2(또는 순수 B안)가 자연스럽다.

## 6. 하이브리드 2 상세 (지망 우선 + 리조트 순서 유지)

우선순위 사다리:

> ① 총 당첨 인원 최대 → ② **개인 지망** → ③ 리조트 순서 → ④ 무작위

### 비용 설계

```
비용 = 지망순위 × 100 + 리조트순번
```

- 지망순위: 1지망 = 1, 2지망 = 2
- 리조트순번: 호반 = 1, 롯데 = 2, 대명 = 3, 오크밸리 = 4, 한화 = 5

리조트 순번 차이는 최대 4라서 지망 한 단계 차이(100)를 절대 못 뒤집는다. 알고리즘은 "비용 합 최소 배정"을 찾을 뿐인데, 이 숫자 설계만으로 "지망이 항상 먼저, 리조트 순서는 동률일 때만"이라는 서열이 자동으로 강제된다.

### 리조트 순서가 실제 작동하는 동률 예시

철수: 1지망 롯데B, 2지망 **호반A** / 영희: 1지망 롯데B, 2지망 **한화C** / 세 객실 모두 정원 1.

- (가) 철수→롯데(1지망), 영희→한화(2지망) → 호반 미충원. 비용 = 102 + 205 = **307**
- (나) 영희→롯데(1지망), 철수→호반(2지망) → 한화 미충원. 비용 = 102 + 201 = **303**

두 안 모두 당첨 2명·지망 만족 동률이지만, 리조트 순서가 개입해 **호반을 채우는 (나)** 를 선택한다.

### 체감 변화

이 구성에서 리조트 순서는 지망 만족도가 완전히 같은 배정안이 여럿 남았을 때만 작동한다. 실데이터(신청 266건, 정원 117석) 규모에서 그런 동률은 드물어, 리조트 순서의 영향력은 지금보다 크게 줄어든다 — "기준으로는 존재하지만 결정하는 일은 가끔". 대신 결과 설명은 명확해진다: **"총원 최대를 전제로 1지망을 최대한 만족시켰고, 동률은 리조트 순서, 그래도 남으면 무작위."**

## 7. 장단점 및 선행 조건

### 장점

- **체감 공정성**: 현재는 리조트 나열 순서·지역 가나다순이라는 신청자가 모르는 기준이 우선권을 정한다. 지망제는 "내가 원하는 순서"가 기준이 되어 결과를 납득시키기 쉽다.
- **선택지메일 프로세스 제거**: 1:1 복수 신청자도 1지망으로 자동 확정되어 메일 발송·수동 배정·당첨자 시트 제외 로직(L794-823, L929-951)이 통째로 불필요해진다.
- **결과 설명력**: "1지망 배정 n명 / 2지망 m명" 통계로 추첨 결과를 투명하게 보고할 수 있다.

### 단점·리스크

- **신청 프로세스 변경 선행 필수**: 현재 신청 양식에 지망 입력이 없다. 상류(신청 폼) 변경 없이는 도입 불가.
- **총원 감소 위험(A안 한정)**: 1지망 절대 우선 방식은 총 당첨 인원이 66 아래로 떨어질 수 있다. B안으로 회피 가능하나 코드 복잡도 상승.
- **규칙 문서 개정 필요**: `rule.md` R2/R4, `explain.txt` ①②③이 리조트 순서 기준으로 규정돼 있어 이해관계자 합의·개정 필요.
- **동순위 타이브레이크 명문화 필요**: 같은 객실을 1지망으로 쓴 사람끼리는 여전히 무작위이므로 규칙으로 명시해야 한다.
